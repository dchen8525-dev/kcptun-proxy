# 参数对照：kcptun-proxy vs FCP (C++ / Node.js)

这一版刻意复用 FCP 白名单的命名和语义，让两边可以用同一份配置习惯跑对比脚本。凡是**没有真实实现**的参数，一律不提供；传进来就是硬错误，不是警告，更不是静默忽略。

## 逐项对照

| FCP 白名单 | kcptun-proxy | 差异与原因 |
| --- | --- | --- |
| `--key=HEX32` | **同名同义** | 同一个 32 hex 字符串、同一个 16 字节 PSK。FCP 用 AES-128-GCM，这边 `kcp.NewAESGCMCrypt` 也是 AES-128-GCM（但帧格式不同，两端不能互通）。 |
| `-b, --bind=IP[:P]` | **同名同义** | `-b` 在两端都表示「本地绑定」。默认端口不同：FCP 4460、FCP-Node 4461、本版 4462（可并存）。 |
| `--peer=IP[:P]` | **同名同义** | 默认端口 4462。server 传 `--peer` 直接报错。 |
| `--mtu-min=N` / `--mtu-max=N` / `--no-pmtud` | **`--mtu=N`** | kcp-go 没有 PMTUD。FCP 的 `--mtu-min` 是「探测起点」，`--mtu-max` 是「探测上限」，`--no-pmtud` 才把它钉死成固定预算；本版只有一个固定预算，所以只剩一个参数。语义保持一致：N 是**含 20B IP + 8B UDP 头**的数据报字节数，内部 `SetMtu(N-28)`。 |
| `--fec=D:P` | **同名，语义收窄** | FCP 的 P 是自适应控制器的**上限**，k 由丢包反馈自己爬；kcp-go 的 P 是固定的 Reed-Solomon 校验分片数，没有控制器。所以 `P=0` 在这边是「关闭 FEC」，在 FCP 里是「不允许任何校验」。 |
| `--trace=PREFIX` | **同名，内容不同** | FCP 输出每会话的 FEC 控制器轨迹；本版输出 `<PREFIX>-<role>-<pid>.jsonl` 的连接事件（session_open / stream_open / open_error / stream_close）。没有控制器可追。 |
| `--log-level=LEVEL` | **同名同义** | `debug\|info\|warn\|error\|off`，日志走 stderr。 |
| `--log-file=PATH` | **同名同义** | 追加写，自动建父目录，失败即退出。 |
| `--speedtest` / `--seconds=N` | **同名，位置不同** | FCP 是子命令 `node cli.ts speedtest --seconds=N`；本版是 client 的开关 `kcptun-client --speedtest --seconds=N`，因为本版是两个独立 exe，没有子命令的位置。都不需要真实服务端。 |
| `-h, --help` | **同名同义** | 首行带版本。`--version` 两边都删了。 |

## 本版独有的参数

只有一个：`--mtu=N`（见上表）。其余都是 FCP 白名单里已有的名字。

## 只在 FCP 存在、本版直接不提供的能力

不列成「参数」是因为列了就会有人以为能开关：

| FCP 能力 | 本版 | 备注 |
| --- | --- | --- |
| PMTUD 探测爬升 | 无 | kcp-go 的 MTU 是静态的 |
| 丢包驱动的自适应 FEC | 无 | kcp-go 的 FEC 分片数固定 |
| ACK v2 / 宽 SACK / CAP_TLV 协商 | 无 | kcp-go 有自己的 ACK 格式，没有 TLV 协商层 |
| #84 epoch key roll | 无 | 会话密钥整个生命周期不变 |
| stateless reset | 无 | 无对应机制 |
| BBR-lite / 发送窗口估计 | 无 | kcp-go 用 KCP 自己的窗口与 `SetNoDelay` 参数 |
| 每本地连接一条独立会话 | 改为 smux 复用 | 一条 KCP 会话承载多条 stream，省掉重复握手 |

## fail-loud 表

`internal/config/config.go` 的 `retiredKnobs` 覆盖两类拼写，命中任何一个都返回 `X is no longer accepted; use Y (原因)`：

**FCP 已删除的旧拼写**：`--host` / `-H`、`--listen` / `-l`、`--local-port`、`--port` / `-p`、`--mtu-min` / `--mtu-max` / `--no-pmtud` / `--pmtud`、`--packet-size` / `-m`、`--parity` / `--k` / `--fec-budget`、`--log`、`--version`、`--key-file` / `--psk-file` / `--key-env`、`--speedtest-seconds`。

**kcptun 官方参数**：`--localaddr` / `--remoteaddr` / `-r`、`-c` / `--config`、`--crypt`、`--mode`、`--nodelay`、`--interval`、`--resend`、`--nc`、`--sndwnd`、`--rcvwnd`、`--dscp`、`--nocomp`、`--sockbuf`、`--smuxver`、`--smuxbuf`、`--streambuf`、`--datashard` / `--parityshard`、`--quiet`、`--tcp`、`--snmp`、`--pprof`、`--autoexpire`、`--acknodelay`、`--compression`、`--scavengettl`、`--keepalive`。

第二类尤其重要：照着 kcptun 教程粘一整行 `--mode fast3 --crypt aes --sndwnd 1024 ...`，如果静默忽略，用户会以为 KCP 被调优了，实际跑的是内置固定 profile（碰巧正好是 fast3，但 `--sndwnd 2048` 这类就会悄悄不符）。所以全部报错，并指向 `docs/InternalProfile.md`。

`--datashard` / `--parityshard` 明确提示改用 `--fec=D:P`；`--localaddr` / `--remoteaddr` 明确提示改用 `-b` / `--peer`。

## 解析行为差异

| 场景 | FCP C++ | FCP Node | 本版 |
| --- | --- | --- | --- |
| 值参数空格分隔（`--fec 10:3`） | 视实现而定 | 拒绝，要求 `=` | **拒绝，要求 `=`** |
| IPv6 带端口 | 不拆端口 | 保留方括号 | Go `net.SplitHostPort` 正确处理 `[::1]:4462` |
| 纯 IPv6 无端口（`::1`） | — | — | 自动补成 `[::1]:4462` |
| 位置参数（`kcptun-client server ...`） | 子命令 | 子命令 | **报错**：exe 本身已经代表角色 |
| 未知参数 | 报错 | 报错 | 报错，并提示 `-h` |
